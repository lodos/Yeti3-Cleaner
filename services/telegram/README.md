# @yeti3cleanerbot — отдельный платёжный бот

Python 3.10+, только стандартная библиотека. Приложения iOS/Mac не содержат ссылок на этот бот. Цифровые функции внутри Telegram оплачиваются Stars (`XTR`); прямой эквайринг рублями/Apple Pay в бот не подставляется. Stars не называются реальными рублями или денежным балансом.

## Конфигурация при развёртывании

Секреты передаются процессу окружением из менеджера секретов, не коммитятся:

- `CLEANER_TELEGRAM_BOT_TOKEN`: токен @yeti3cleanerbot.
- `CLEANER_NETWORK_WORKER_TOKEN`: отдельный серверный worker credential; его SHA-256 должен быть настроен в `NETWORK_TELEGRAM_WORKER_TOKEN_HASH` лицензирования. Это другой секрет, не Telegram bot token и не админский токен.
- `CLEANER_WEBHOOK_SECRET`: случайная строка минимум 32 символа, допустимая Telegram для webhook secret_token.
- `CLEANER_STARS_ENABLED=true`: включать после изолированной проверки серверных платежей/возвратов; реальный денежный E2E проверять отдельно, связки аккаунта и тарифа Stars.
- `CLEANER_AUTHORITY_ORIGIN=http://127.0.0.1:4352`: внутренний сервер подтверждения. Публичные `/internal/` закрыты и для этого не подходят.
- `CLEANER_TELEGRAM_RELAY`: необязательный Unix-сокет существующего TCP relay; сертификат и hostname Telegram проверяются самим ботом.
- `CLEANER_BOT_PORT=8097`: слушает только loopback. Reverse proxy должен предоставить HTTPS `/webhook`, ограничение частоты и тела. До запуска проверьте текущий webhook бота: два потребителя одного бота недопустимы.

Запуск: `python3 bot.py`. Регистрация HTTPS webhook выполняется оператором через Telegram `setWebhook` с тем же `secret_token`, `allowed_updates=["message","pre_checkout_query","callback_query"]`, без сброса ожидающих сообщений. При повторной настройке сохранить очередь; `drop_pending_updates` не включать. Развёртывание 2026-10-11: webhook `https://license.gochain.space/api/cleaner/telegram/webhook` зарегистрирован, очередь сохранена. Сервис и приватный TLS relay работают под отдельными системными пользователями; существующие права общего relay не расширялись. Проверка getMe выполнена от UID бота. Реальных списаний и сообщений пользователям при проверке не отправляли.

Пользователь связывает Telegram с существующим аккаунтом сети, читает `/terms`, выбирает `/buy 1` или другой поддерживаемый срок и отдельно принимает условия. Цена приходит из сервера, счёт действует один час. `pre_checkout_query` только проверяет заказ. Доступ выдаёт существующий сервер после `successful_payment`, проверки пользователя/заказа/валюты/суммы и записи charge ID. Повторы идемпотентны на сервере; после сбоя webhook отвечает 503, Telegram повторяет доставку. `refunded_payment` пересчитывает права через сервер. Возврат инициирует оператор через Telegram `refundStarPayment`, затем проверяет доставку события и отзыв доступа. `/paysupport` и `/support` дают контакт владельца.

Локальных баз, SQLite, баланса бонусов и клиентского переключателя выдачи доступа нет. HTTP-логи отключены; данные платежа не выводятся. Не раскрывать worker credential публичным фронтендам.

Проверка без сети и секретов: `python3 -m unittest discover -s services/telegram -v` из корня репозитория. Проверяет запрет выдачи по precheckout/обычному сообщению, валюту, оплату/возврат, согласие с условиями, отключённый checkout и отказ сервера. Это не доказательство реального платежа Telegram. `verify_authority.py` дополнительно проверяет тот же запущенный Rust-образ и MySQL в отдельной временной схеме: создание счёта, сумму, отсутствие доступа по precheckout, подтверждение, повтор, продление и возврат. Синтетические charge ID никогда не записываются в production. Реальный пользовательский платёж и возврат через Telegram остаются отдельной приёмочной проверкой.

## Эксплуатация

Канонические секреты: GoChain Keychain, записи `telegram/yeti3cleanerbot/admin` и `telegram/yeti3cleanerbot/payments`. Не копировать значения в Git, чат или логи. `install.py` запускается root-оператором из проверенной staged-копии; получает секреты через `/usr/local/bin/yeti3-keychain`, сохраняет root-only EnvironmentFile, проверяет текущий webhook, текущий образ и credential authority, nginx -t и публичный маршрут. Он управляет только сервисами Cleaner. Старый образ не заменяет автоматически при несовпадении. Резервные копии nginx и своего бота: `/var/backups/yeti3-cleaner-bot/`. Для отключения новых покупок установить `CLEANER_STARS_ENABLED=false` в собственном runtime.env и перезапустить только `yeti3-cleaner-bot`; обработку уже оплаченных событий сохранять.

На origin развёрнут отдельный `yeti3-cleaner-ad-authority` из точного образа действующего `gochain-site-advertising`, с отдельным worker credential и loopback-портом. Основной контейнер рекламы не перезапускался. Серверный аудит фиксирует изменения тарифа и прав.

### Расчёт Stars на 2026-10-11

По поручению владельца применён множитель 3. Измеренной себестоимости на аккаунт нет: временной расчётной базой служит существующая центральная USD-сетка. Это предположение, а не результат измерения затрат. `stars_per_usd = ceil(3 / 0.013) = 231`; каждый счёт: `ceil(usd_cents × 231 / 100)`. Эквивалент награды 0.013 USD/Star взят из [условий Telegram](https://telegram.org/tos/bot-developers), §6.2.4; он не является розничной ценой Stars, налогом или гарантией вывода средств. USD-сетка и скидки не изменены.

## Проверка 2026-10-11

15 unit/HTTP-boundary тестов проходят. В изолированной MySQL-схеме на точном production-образе проверены 12 сценариев прав, сумм, precheckout, двух оплат, replay и двух возвратов; production rows written = 0, временные схема/контейнер удалены. Runtime-хеш bot.py совпадает с исходником, systemd active/running, checkout_enabled=true. Webhook зарегистрирован, запрос без секрета получает 403. Реальная оплата Stars и возврат ещё не выполнялись; готовность сервиса не является доказательством денежной транзакции.
