# @yeti3cleanerbot — отдельный платёжный бот

Python 3.11+, только стандартная библиотека. Приложения iOS/Mac не содержат ссылок на этот бот. Цифровые функции внутри Telegram оплачиваются Stars (`XTR`); прямой эквайринг рублями/Apple Pay в бот не подставляется. Stars не называются реальными рублями или денежным балансом.

## Конфигурация при развёртывании

Секреты передаются процессу окружением из менеджера секретов, не коммитятся:

- `CLEANER_TELEGRAM_BOT_TOKEN`: токен @yeti3cleanerbot.
- `CLEANER_NETWORK_WORKER_TOKEN`: отдельный серверный worker credential; его SHA-256 должен быть настроен в `NETWORK_TELEGRAM_WORKER_TOKEN_HASH` лицензирования. Это другой секрет, не Telegram bot token и не админский токен.
- `CLEANER_WEBHOOK_SECRET`: случайная строка минимум 32 символа, допустимая Telegram для webhook secret_token.
- `CLEANER_STARS_ENABLED=true`: включать только после сквозной проверки тестовых платежей/возвратов, связки аккаунта и тарифа Stars.
- `CLEANER_BOT_PORT=8097`: слушает только loopback. Reverse proxy должен предоставить HTTPS `/webhook`, ограничение частоты и тела. До запуска проверьте текущий webhook бота: два потребителя одного бота недопустимы.

Запуск: `python3 bot.py`. Регистрация HTTPS webhook выполняется оператором через Telegram `setWebhook` с тем же `secret_token`, `allowed_updates=["message","pre_checkout_query","callback_query"]`, без сброса ожидающих сообщений. При повторной настройке сохранить очередь; `drop_pending_updates` не включать. Бот в этой работе не запускался, webhook не заменялся, реальные сообщения не отправлялись.

Пользователь связывает Telegram с существующим аккаунтом сети, читает `/terms`, выбирает `/buy 1` или другой поддерживаемый срок и отдельно принимает условия. Цена приходит из сервера, счёт действует один час. `pre_checkout_query` только проверяет заказ. Доступ выдаёт существующий сервер после `successful_payment`, проверки пользователя/заказа/валюты/суммы и записи charge ID. Повторы идемпотентны на сервере; после сбоя webhook отвечает 503, Telegram повторяет доставку. `refunded_payment` пересчитывает права через сервер. Возврат инициирует оператор через Telegram `refundStarPayment`, затем проверяет доставку события и отзыв доступа. `/paysupport` и `/support` дают контакт владельца.

Локальных баз, SQLite, баланса бонусов и клиентского переключателя выдачи доступа нет. HTTP-логи отключены; данные платежа не выводятся. Не раскрывать worker credential публичным фронтендам.

Проверка без сети и секретов: `python3 -m unittest discover -s services/telegram -v` из корня репозитория. Проверяет запрет выдачи по precheckout/обычному сообщению, валюту, оплату/возврат, согласие с условиями, отключённый checkout и отказ сервера. Это не доказательство реального платежа Telegram: до запуска необходим тестовый Telegram environment, защищённый webhook и тестовый аккаунт лицензирования.
